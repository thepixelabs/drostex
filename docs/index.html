> field notes

The spec sheet stops where the wiring starts.

The vendor publishes the counts, and on the Nano they hold: 132 LEDs, 12 edges of 11, 95 effects. What nobody publishes is how those LEDs are addressed. The controller reports 88 addresses and only 44 drive anything, the wiring is branching-parallel with uneven fan-out, and edges that share a block always show the same colour. So you get 44 controllable pixels, not 132. The scripts that found that ship in scripts/, so you can re-run them on your own unit instead of trusting ours.

> architecture

Two things can drive the cube. Never both.

A browser cannot open a raw UDP socket, so a small Node server holds the socket and does the pixel maths instead. The page only ever sends control messages over HTTP. Close the tab and the animation keeps running.

source A: yours

Streamed looks

Computed in Node, pushed over WLED DRGB on UDP 21324 at up to 60 fps.

  • 11 built-in patterns, plus a Custom node you assemble yourself
  • Per-pattern parameters, saved independently as you switch around
  • Gamma applied after brightness, so dimming stays perceptually even
  • Drift-corrected frame clock, so timer jitter cannot accumulate
source B: the firmware's

Built-in effects

The cube's own ~95 effects and 3 rotating playlists, driven over its JSON HTTP API.

  • Star the ones you like; filter to sound-reactive or static
  • 25 of the firmware's 27 palettes, with hand-authored swatches so you can pick by eye
  • Symmetry, speed, intensity and palette each show whether you or the pattern currently owns them
  • Warp drive, the one-shot animation baked into the firmware

The handover only runs one way. Realtime pixels override whatever the firmware draws the instant they arrive, so starting a look needs no handshake: the stream simply wins. Picking an effect is the direction that needs care, because the reverse isn't true. Drostex releases the socket first, without blanking it, so the handoff doesn't flash black between the two sources. Auto-cycle follows the same rule mid-rotation.

> quick start

Two commands, no build step.

There are no runtime dependencies. Everything it needs ships with Node. Nothing to install, no native module to compile. That is the difference between "clone and run" and "clone and debug node-gyp".

01

Get it

Needs Node 20 or newer. That is the only prerequisite.

git clone https://github.com/thepixelabs/drostex
cd drostex

02

Run it

Opens your browser. No cube configured yet? It looks for one on the network automatically.

npm start
# http://127.0.0.1:7847

optional

Point it at a specific cube

Only if automatic discovery finds nothing, or finds the wrong device.

cp config.example.json config.json
# "host": "192.168.1.50"

What day one looks like: click a pattern and it is already running on the cube before you let go of the mouse. Hit Shuffle until something surprises you. Save it. Turn on Auto-cycle and walk away: it keeps working through your saved looks and the firmware's own effects with nobody at the keyboard.

> extending it

An animation is one pure function.

Take a context, return [r, g, b] in 0..1. Declare the parameters you want exposed, and the UI builds its controls from those declarations. Adding a knob is a one-line change that needs no UI work at all.

Two coordinates, and the difference matters. u runs i/(N-1) and hits both endpoints exactly. uw runs i/N and wraps. The strip is a closed loop whose ends meet at the corner the cube stands on, so a hue ramp built on u puts a visible colour break right there. That was a real bug report, and it is why both exist.

Drop it into src/animations.mjs. It shows up in the UI, in the CLI player, in auto-cycle and as a savable look. No registration step. 

// src/animations.mjs
rainbow: {
  label: 'Rainbow',
  desc: 'a hue cycle travelling around the loop',

  // Each entry becomes a labelled control.
  params: {
    cycles:     num('Cycles', 1, 1, 4, 1),
    saturation: num('Saturation', 0.95, 0, 1),
    drift:      num('Drift', 0.15, -1, 1),
  },

  // uw wraps, so the loop closes with no seam.
  fn: ({ uw, t, speed, p }) =>
    hsv(uw * p.cycles + t * p.drift * speed,
        p.saturation, 1),
},

> the honest part

What it does not do.

Built on one cube on one desk. These are the things that would make you regret cloning. The smaller print is in the README.

  • one cubeA HyperCube Nano on firmware hs-2.0, one unit, one cube per server. The HyperCube10-SE and 15-SE are configured from the vendor's spec sheet and have never been run against a real one. If you own one, we want to hear from you.
  • not stock WLEDStreamed looks should reach any WLED device that accepts DRGB on port 21324; run scripts/blink.mjs against yours first. The built-in-effects tab reads index ranges off this firmware's own effect list, and will not work on plain WLED.
  • no authBinds to 127.0.0.1 and rejects non-loopback Host headers. The Remote switch opens it to your phone, and to everyone else on the network, until you switch it off. That is a guard, not a security model. Do not expose it beyond a network you trust.
  • not packagedNode, a terminal, and a process you leave running. Close the laptop and the animation stops.
  • no audioSound-reactive effects use the microphone on the cube itself. Drostex sends none, so they look broken in a silent room.

Approximate palette swatches, why a brightness reading of 255 is never adopted, no hot reload, the nominal edge layout in the preview: all in the README's Limitations.

> questions

The HyperCube, answered.

The vendor publishes the spec sheet: the counts, the protocol names, what the app does. It does not publish how the LEDs are actually addressed, or what the controller really speaks. Those answers came from measuring a real Nano, and the scripts that produced them ship in the repository, so you can re-run every one against your own cube.

What is the Hyperspace HyperCube Nano?

A desk-sized LED infinity mirror cube. It stands on one corner, its twelve edges are lit by 132 LEDs, and it runs a rebranded fork of WLED on an ESP32, reporting itself as firmware hs-2.0. It ships with 95 built-in effects, 27 palettes and three rotating playlists, all selected from the cube's own web page or from its buttons.

Can you write your own effects for the HyperCube Nano?

Not with the stock firmware. The 95 effects are compiled in and there is no way to add a 96th. Drostex works around that by taking over the pixels: it computes frames on your own machine and streams them to the cube as realtime data, so an effect you write in about ten lines of JavaScript runs on the object exactly like a built-in one.

Does the HyperCube Nano run WLED, and does it accept WLED apps?

It runs a WLED fork, so it answers the standard WLED JSON HTTP API and accepts WLED realtime UDP. Generic WLED tools that only set effects and colours will usually work. Tools that expect stock WLED's full config surface will not: /json/cfg answers 501 on this firmware, and the effect list, the sound-reactive block, the symmetry modes and the warp animation are vendor additions that plain WLED does not ship.

How many LEDs does the HyperCube Nano actually have?

132 LEDs over 12 edges of 11, which matches the vendor figure. The controller reports 88 addresses, but only the first 44 drive anything: addresses 44 to 87 are configured with no physical tap behind them. So you get 44 independently controllable pixels, not 132.

Why can't each edge of the HyperCube Nano show a different colour?

The wiring is branching-parallel. One data line enters on an edge and splits at the corners, and every edge downstream of a split carries the same signal, so those edges always show the same colour. The fan-out is uneven: the four address blocks drive 1, 2, 4 and 5 edges. That is why there is no single LEDs-per-address figure, and why radial, symmetric and blooming patterns suit this hardware while per-edge independent control does not.

What network protocols does the HyperCube Nano accept?

Measured on firmware hs-2.0: WLED DRGB on UDP port 21324 works and is what Drostex streams on, and sACN / E1.31 on universe 1, port 5568 works too. DDP and Art-Net are closed. The JSON HTTP API answers for control-plane calls, though /json/fxdata returns 501, so effect metadata has to be inferred rather than read.

Is there a desktop app or editor for the HyperCube Nano?

Drostex is one, and it is free and open source under the MIT licence. It runs a small Node server on your own machine and opens a browser UI on 127.0.0.1. A QR button in the top bar switches Remote on and opens the same UI on your phone. There is no cloud account, no signup and no telemetry, and every network call it makes goes either to your cube's LAN address or to its own local API.

Why do some HyperCube Nano effects look like nothing is happening?

About 31 of the built-in effects are sound-reactive and use the microphone on the cube itself. In a quiet room they render almost nothing, which looks broken but is not. Drostex marks those effects so you can filter them out, or rotate only through them when there is music playing.

Does Drostex work on the HyperCube 10 or 15?

The current HyperCube10-SE and HyperCube15-SE, in principle yes: they are the same controller family, and Drostex knows their LED counts from the vendor's spec sheet, 216 LEDs at 18 per edge and 336 at 28. It recognises them from the cube's own /json/info and streams to every address the controller reports. What nobody has measured is whether that controller, like the Nano's, reports more addresses than drive LEDs, or how the edges gang together. If you own one, run scripts/diagnose.mjs and tell us what lit up. The older, non-SE 10 and 15 use a different controller and have not been tried.

Will Drostex work on other WLED devices?

The streaming half plausibly will, on anything that accepts DRGB on port 21324, though it has only ever been run against one HyperCube Nano. The built-in effects tab will not work on stock WLED, because the effect index ranges and the sound-reactive classifier are read off this firmware's own effect list. Run scripts/blink.mjs against your device to find out what it accepts before relying on it.
